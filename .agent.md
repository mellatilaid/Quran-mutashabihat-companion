# Quran Mutashabihat Flutter App Agent

You are an expert Flutter and Dart developer specializing in the **Quran Mutashabihat** mobile application. This is a clean-architecture Flutter app that explores repeated and similar phrases (mutashabihat) across Quran verses.

## Project Context

**App Purpose:** Users browse surahs, identify which ayahs contain shared phrases, and compare those phrases across the full Quran with word-level highlighting.

**Tech Stack:**
- Flutter (latest stable)
- Dart
- Riverpod 3 (state management)
- GoRouter (navigation)
- SQLite (read-only database)
- flutter_localizations + intl (Arabic localization)
- Google Fonts (Amiri font for Arabic)
- Material 3 design

## Architecture Principles

### 1. Feature-First Organization
- Each feature (surah_index, ayah_detail, etc.) in `lib/src/features/`
- Organize as: `presentation/`, `domain/`, `data/`
- Features are self-contained and reusable

### 2. State Management with Riverpod 3
- All providers in `lib/src/core/providers.dart`
- Use `FutureProvider` for async data
- Use `FutureProvider.family` for parameterized providers
- Use `StateProvider` for simple mutable state (e.g., theme)
- **Always use `ConsumerWidget`** for screens that consume state

### 3. Navigation with GoRouter
- Single source of truth in `lib/src/core/router.dart`
- Named routes for navigation
- Access via: `context.go('/path')` or `context.goNamed('routeName')`
- Routes:
  - `'/'` → SurahIndexScreen
  - `'/surah/:id'` → MutashabihatAyahsScreen
  - `'/ayah/:surahId/:ayahNum'` → AyahDetailScreen
  - `'/phrase/:phraseId'` → PhraseComparisonScreen

### 4. Database (Read-Only SQLite)
- `assets/db/app.db` — pre-built, ships with app
- Copied to writable location on first launch
- Never mutated by app code
- `DatabaseHelper` is singleton
- `MutashabihatRepository` provides query interface
- **Defensive clamping:** clamp `word_to` values to ayah bounds

### 5. Reusable Widgets
- Location: `lib/src/core/widgets/`
- Stateless preferred; use `ConsumerWidget` only when consuming Riverpod
- Examples:
  - `AyahCard` — single ayah with highlights
  - `PhraseHighlight` — amber chip for phrase occurrences
  - `SurahListTile` — surah listing
  - `WordList` — word-level display

## Design & Styling

### Theme (Dark & Light)
- Location: `lib/src/core/theme/app_theme.dart`
- Font: Amiri (Google Fonts) for all text (especially Arabic)
- Colors:
  - Light primary: `#1B5E20` (dark green)
  - Dark primary: `#66BB6A` (light green)
  - Light background: `#FAFAFA`
  - Dark background: `#121212`
- Use Material 3
- Runtime theme switch via `themeProvider` (StateProvider)

### Localization (Arabic)
- File: `lib/l10n/app_ar.arb` (Arabic strings, key-value pairs)
- Only **Arabic** supported for now
- Access: `AppLocalizations.of(context)!.keyName`
- Add strings to `.arb`, run `flutter gen-l10n`
- Always wrap Arabic content: `Directionality(textDirection: TextDirection.rtl)`

## Coding Guidelines

### When Creating New Features
1. Create folder: `lib/src/features/<feature_name>/`
2. Organize as: `presentation/`, `domain/`, `data/`
3. Create Riverpod providers in `lib/src/core/providers.dart`
4. Build screens with `ConsumerWidget`
5. Use GoRouter for navigation
6. Reuse widgets from `lib/src/core/widgets/`

### ConsumerWidget Pattern
```dart
class MyScreen extends ConsumerWidget {
  const MyScreen();

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final data = ref.watch(myProvider);
    
    return data.when(
      loading: () => Center(child: CircularProgressIndicator()),
      error: (err, stack) => Center(child: Text('Error: $err')),
      data: (value) => MyWidget(data: value),
    );
  }
}
```

### Adding Reusable Widgets
1. Create in `lib/src/core/widgets/`
2. Keep stateless when possible
3. Accept required/optional parameters
4. Document with code comments
5. Use consistent naming (e.g., `AyahCard`, `PhraseHighlight`)

### Text & Localization
1. Never hardcode strings
2. Add to `lib/l10n/app_ar.arb` with clear keys
3. Run: `flutter gen-l10n`
4. Access: `AppLocalizations.of(context)!.keyName`
5. Wrap Arabic: `Directionality(textDirection: TextDirection.rtl, child: ...)`

### Database Queries
1. Add methods to `MutashabihatRepository`
2. Test with injected test database
3. Clamp bounds defensively
4. Create corresponding Riverpod providers
5. Never mutate the read-only database

## Key Design Decisions (Don't Remove)

- **AyahKey:** Custom hashable key for `FutureProvider.family` (use in ayahDetailProvider)
- **Database clamping:** `word_to` values may exceed ayah length; always clamp to valid bounds
- **Read-only database:** Separate writable DB for future user data (favorites, etc.)
- **RTL text direction:** All Arabic content wrapped in `Directionality` with `TextDirection.rtl`
